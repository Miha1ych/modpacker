# Miha1ych Packer

Сайт состоит из трёх разделов, переключаются вкладками в шапке (`.top-nav`
в каждом HTML-файле — единый сегмент-контрол, без эмодзи в подписях):

- **Пакер** (`index.html` + `js/app.js`) — мастер сборки модпака, описан ниже.
- **Проверка на вирусы** (`virus-check.html` + `js/virus-check.js` +
  `js/jar-analyzer.js`) — только через загрузку своего `.jar`, без Modrinth.
  Сайт разбирает файл прямо в браузере (никуда не отправляется): парсит
  constant pool каждого `.class`-файла (без полной декомпиляции — только
  заголовок класса, где лежат все строки и ссылки на используемые
  классы/методы) и ищет тревожные паттерны — запуск процессов
  (`Runtime.exec`/`ProcessBuilder`), сокеты, Discord-вебхуки, обращение к
  папкам с паролями браузера/токенами Discord, исполняемые файлы внутри
  архива и т.п. (полный список сигнатур — в начале `js/jar-analyzer.js`).
  Это эвристика по паттернам, а не ИИ и не настоящий антивирус — так и
  написано на странице. Отдельно считаем SHA-1 файла и даём ссылку на поиск
  по этому хешу на VirusTotal.
- **Перепаковка текстурпаков** (`repack.html` + `js/repack.js`) — загружаешь
  .zip ресурспака, сайт находит `pack.mcmeta`, по таблице соответствий
  (`PACK_FORMAT_TABLE` в `js/repack.js`, с minecraft.wiki/w/Pack_format)
  пересчитывает `pack_format` под выбранную версию и отдаёт новый ZIP —
  всё через JSZip прямо в браузере. Структуру папок/текстур пак не трогает,
  это осознанное ограничение, обозначено в интерфейсе. Единственный из трёх
  разделов, кроме «Пакера», который всё ещё стучится в Modrinth API — но
  только за списком версий Minecraft (`/tag/game_version`), не за модами.

`js/common.js` содержит общие мелочи (обёртку над Modrinth API, форматирование
чисел, `debounce()`, рендер карточки проекта `resultCardHTML()`). Раздел
«Зеркало Модринта» (`mirror.html` + `js/mirror.js`) временно убран из
навигации по просьбе — файлы остались в проекте, но никакая страница на них
больше не ссылается.

## Раздел «Пакер»

Пользователь проходит мастер из шагов —
категория сборки → загрузчик модов → версия Minecraft → ядро рендера
(каждый шаг анимированно сменяет предыдущий, с кнопкой «Назад»). Версия
специально идёт раньше ядра: как только версия и загрузчик известны, сайт
сразу проверяет на Modrinth, какие ядра под них реально собраны, и
блокирует недоступные (например VulkanMod под старый Forge) прямо на
карточке — вместо того чтобы узнать об этом только после полного подбора
модов. Дальше сайт спрашивает [Modrinth API](https://docs.modrinth.com/api/),
какие моды из курируемого списка совместимы, и упаковывает выбранные `.jar`
прямо в браузере в один ZIP через [JSZip](https://stuk.github.io/jszip/).

Визуально — тёмная тема в стиле "жидкого стекла" (frosted glass) в винной
палитре: полупрозрачные панели с блюром и плотной тёмной подложкой (не
просто прозрачность — иначе текст сливается с фоном) поверх мягкого
винно-розового свечения. Текст — тёплый off-white (`#F8EDEF`), а не чистый
белый, это тоже осознанный выбор против слияния с фоном.

Файлы модов скачиваются напрямую из браузера пользователя с `cdn.modrinth.com` —
сайт ничего не хостит и не проксирует сам, поэтому GitHub Pages вполне достаточно.

## Структура проекта

```
index.html         — разметка страницы (мастер шагов + результаты)
css/style.css       — оформление ("жидкое стекло", тёмная тема)
js/mods-data.js     — курируемые категории, ядра рендера и список slug'ов модов
js/app.js           — вся логика: мастер шагов, Modrinth API, сборка ZIP
```

## Как это работает технически

1. **Категории и кандидаты** живут в `js/mods-data.js`. Для каждого мода
   хранится не прямая ссылка на файл, а slug проекта на Modrinth (и иногда
   несколько альтернативных slug'ов — например `starlight` / `starlight-forge`
   для одного и того же мода под разные загрузчики).
2. **Ядро рендера** (`engines` в категории) — отдельный обязательный шаг
   мастера для категорий, где это применимо (сейчас — «Оптимизация»: Sodium,
   Embeddium, Rubidium или VulkanMod), идёт ПОСЛЕ версии. Embeddium и
   Rubidium — два независимых форка Sodium под Forge/NeoForge (FML);
   Embeddium активно поддерживается и обычно стоит выбрать его, но Rubidium
   до сих пор нужен для части старых сборок, поэтому показаны обе карточки,
   а не только одна как fallback. Как только пользователь попадает на
   этот шаг, `checkEngineAvailability()` в `js/app.js` спрашивает Modrinth
   по каждому ядру для уже выбранных загрузчика+версии и блокирует
   (`disabled` + серая подпись с причиной) те, для которых сборки нет —
   их физически нельзя выбрать. Ядра взаимоисключающие (не чекбокс, а
   единственный выбор), резолвятся так же, как обычный мод-кандидат. Моды,
   которые имеют смысл только при конкретном ядре (например Sodium Extra),
   лежат в `engineOptional[engineId]`.
3. При нажатии «Подобрать моды» сайт делает запросы вида:
   `GET /v2/project/{slug}/version?loaders=["fabric"]&game_versions=["1.21.1"]`
   — если есть хотя бы один результат, мод показывается как доступный вместе
   с актуальным файлом. Если нет — попадает в «Недоступно для этой версии».
   Это значит, что список **не протухает** при выходе новых версий
   Minecraft. Список версий тоже приходит с сервера — снапшоты сознательно
   отфильтрованы (под них почти никогда нет модов).
4. При скачивании сайт также вытаскивает `required`-зависимости каждого мода
   (например Fabric API) из поля `dependencies` версии и докачивает их
   автоматически, отмечая как зависимость в манифесте архива.
5. Все файлы качаются `fetch()`'ем прямо в браузере пользователя и
   упаковываются в ZIP через JSZip — сервер (и сам сайт) их не видит и не
   хранит.

## Мастер шагов и анимация

`js/app.js` хранит текущий шаг как индекс в динамическом массиве
`stepsOrder` (шаг «Ядро рендера» подставляется в цепочку, только если у
выбранной категории есть `engines`). Переключение шагов — не просто
show/hide: текущая карточка получает класс `leave-fwd`/`leave-back`
(уезжает и гаснет), через 300мс скрывается, а следующая проявляется с
противоположной стороны (`enter-fwd-start`/`enter-back-start` → снятие
класса на следующем кадре). Все переходы объявлены в `css/style.css` в
блоке `.wizard-step`.

## Как добавить новую категорию

Открой `js/mods-data.js` и добавь новый ключ в объект `CATEGORIES`, например:

```js
visuals: {
  id: 'visuals',
  title: 'Визуал',
  emoji: '🎨',
  tagline: 'Шейдеры и текстуры',
  core: [
    { slugs: ['iris'], note: 'Загрузчик шейдеров, совместим с Sodium' },
  ],
  optional: [],
  // engines необязателен — если его нет, шаг выбора ядра просто пропускается
},
```

Больше ничего менять не нужно — UI сам подхватит новую категорию.

## Как разместить на GitHub Pages

1. Создай новый репозиторий на GitHub (например `miha1ych-packer`) и залей
   в него все файлы этого проекта (можно просто перетащить папку через
   веб-интерфейс GitHub, либо через git):

   ```bash
   git init
   git add .
   git commit -m "Initial commit"
   git branch -M main
   git remote add origin https://github.com/<твой-ник>/miha1ych-packer.git
   git push -u origin main
   ```

2. В репозитории зайди в **Settings → Pages**.
3. В разделе **Build and deployment** выбери источник **Deploy from a branch**,
   ветку `main` и папку `/ (root)`.
4. Сохрани — через минуту-две сайт будет доступен по адресу вида
   `https://<твой-ник>.github.io/miha1ych-packer/`.

Обновлять сайт дальше — просто `git push` новых изменений в `main`.

## Ограничения и заметки

- Modrinth API не требует ключа для чтения и разрешает CORS-запросы из
  браузера, но имеет лимит на количество запросов в минуту — при резком
  наплыве пользователей возможны ошибки 429 (сайт покажет понятное
  сообщение и попросит подождать).
- Для Quilt совместимость ищется и по тегу `quilt`, и по `fabric` (Quilt
  умеет запускать фабриковские моды), это осознанное упрощение.
- VulkanMod как ядро доступен только для Fabric/Quilt/NeoForge (нет сборки
  под классический Forge); Sodium как ядро в старых версиях Forge/NeoForge
  тоже часто недоступен (используй Embeddium/Rubidium) — во всех таких
  случаях карточка ядра на шаге мастера просто заблокирована с подписью
  причины, ничего собирать не придётся вручную.
- CurseForge не используется намеренно: его API требует ключ и жёстче
  регулирует правила на скачивание файлов сторонними сайтами.
- Тема сайта — сознательно только тёмная (не подстраивается под светлую
  системную тему): жидкое стекло держится на контрасте с цветными пятнами
  на тёмном фоне, на светлом фоне эффект теряется.
- Соблюдай лицензии авторов модов — сайт лишь помогает скачать то, что и так
  доступно публично на Modrinth.
